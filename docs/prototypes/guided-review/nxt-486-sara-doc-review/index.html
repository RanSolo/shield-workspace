SARA Data Flow and Access Query Mapping

Purpose

This document records the current SARA Tier II data flow from the Access frmAutoXML form through XML creation and final delivery. It is intended to support the SARA reorganization spike by identifying Access forms, macros, and queries involved in processing; movement from source tables to staging tables to Tier II export tables; loop boundaries and sequential processing behavior; XML generation and file output behavior; and current bottlenecks, operational assumptions, and risks.

This is a description of the observed legacy implementation. It does not propose a replacement design.

Quick Summary

  1. Access data preparation: frmAutoXML processes one SARA code at a time, clears/rebuilds SARASingle, and appends facility/contact/phone/chemical/location/attachment/state-specific rows into linked Tier II tables.
  2. CGI serialization: create-sara-xmls.cgi reads every facility in SaraTier2Facilities, builds one XML document per facility, and writes to data/SaraXml/Hold/.
  3. Planetpress File Delivery: a batch script creates a Planetpress trigger and moves/zips XML and SitePlan files for delivery.

The Access preparation stage relies on shared temporary staging tables and only one user can safely run the process at a time.

End-to-End Flow

The document walks through frmAutoXML, Auto Run, per-code staging rebuild, validation gate, Tier II table construction, state-specific processing, XML creation, and Create/Send Zip Files.

Command1 / Auto Run

On frmAutoXML, Command1 is captioned Auto Run and runs mcrAutoPopulateTablesRun. That macro prompts the user, then runs mcrAutoPopulateTables with repeat expression [Forms]![frmAutoXML]![Code] Is Not Null.

mcrAutoPopulateTables sets TempVar varCode, runs mcrProcessSARA, runs mcrPrintProcessEncamp, closes frmProcessSARA, and advances to the next record.

Rebuild of per-code staging data

mcrProcessSARA clears SARASingle, runs qryAppendToSARASingleByCode, clears SaraSingleEhs, runs qryEhsSaraSingle, deletes EmailSARA and EmailSARATier2Submit rows, and updates SARASingle.TotalPage.

Linked SQL Server Tier II tables

The document lists linked SQL Server staging tables written by Access and then read by CGI, including Tier2Facilities, Tier2FacilityIDs, Tier2Contacts, Tier2Phone, Tier2ChemicalsInInventory, Tier2ChemInvLocations, Tier2SitePlanLink, and Tier2ContainerLocation.

It notes these are wiped after a batch has been fully processed.

Source and helper tables

The page identifies source/helper data including FacilitySARA, EverythingSARA, ProductsSARA, Asmark, SERCStateInfo, CWResponses, eFileArchive, NAICSDescriptions, VirginChemList, and related location/state tables.

Looping and Sequential Processing Points

The Access loop repeats mcrAutoPopulateTables while [Forms]![frmAutoXML]![Code] Is Not Null. Each iteration advances to the next Code record.

The CGI script selects every FacilityRecordID from SaraTier2Facilities and serially processes every facility. Within each facility, chemical, mixture, storage-location, contact, and phone reads are nested loops.

Bottlenecks and Risks

  • The process is driven by one Access form and one user's macro session.
  • Macro actions are serial and do not allow for parallel work.
  • Shared local staging tables represent the current iteration, so concurrent users would overwrite each other's staging state.
  • A failure or stop condition occurs inside the sequential chain and requires operational intervention before continuing.
  • Partial completion can leave some Tier II tables populated while later tables or later facilities are incomplete.
